Maintenance policy supplied equally to both arms: Eval-only edits use eval-curator then consistency-qa. Skill content edits use skill-author; changed risk/mode coverage also needs eval-curator. Every actual change needs consistency-qa running validate, test and evals. A QA failure routes to the responsible author/curator and must pass recheck before later stages. Changed trigger descriptions need trigger-boundary-auditor after QA. Release-manager is used only for an explicit release request after gates pass. Using skills on another repository is not plugin maintenance. Missing change scope requires clarification, not assumed publication.
