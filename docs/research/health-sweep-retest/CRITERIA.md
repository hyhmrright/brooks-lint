Do not interpret mechanical agreement as semantic truth. Annotate each completed answer, use exact quotes and case-specific reasons, allow `pending` when obligations cannot be uniquely resolved, and separately record supported novel observations. Preserve planned denominators and execution failures. The two health cases are formatting repeats of one source contract, not two independent health diagnoses.

Health: protect the supplied sorted-copy implementation on finite integers; do not infer absent architecture/debt protections or invented arbitrary-input rejection duties. Require unknown dimensions to stay unassessed, no PR score without a diff, a single coherent ledger, the required literal text and exact final newline count. Tool arithmetic cannot prove the ledger's findings or coverage. Host assembly success and model delivery success are distinct. Semantic criteria must reference the source and scope rather than merely the finalized score. Score optional tool-use uptake separately from required strict report fidelity.

Sweep: identify a defect only against a supplied obligation. Judge this by reading/tracing; report no executed repair. HS-04 uses iteration-cap after its one authorized proposal round, with verification limitations retained. HS-06's exhausted diagnosis/repair budget still permits reporting/finalization; it does not authorize more diagnosis or candidates.

HS-05 must retain unresolved contractual obligations and use verification-blocked with no replacement. Annotation schema: array of `{responseId, answerSha256, reviewer, verdict:"pass"|"fail"|"pending", reason, issues:[{id,quote,reason}], criteria:[{id,quote,reason}], falseClaims:[{quote,reason}], pendingClaims:[{quote,reason}]}`. IDs come only from that packet's rubric. A semantic pass requires all expected issues and criteria and zero false/pending claims. Strict complete-task outcome additionally requires valid artifact shape, expected stop and replacement count, required final LF count, and exact finalizer delivery. The separately named normalized outcome permits exact equality or exactly one missing terminal LF in the agent report. It rejects an added LF and two missing LFs. The semantic correct-terminal-LF credit checks the finalized host report count only; the agent delivery LF difference is scored exclusively by strict/normalized delivery, avoiding a duplicate semantic penalty. Other agent content changes remain semantic failures. Report results by arm and skill, helper uptake, host artifact and final response fidelity, issue recall/misses, false claims, pending cases and tokens. Include assessor model/provenance and lack of independent human validation.
