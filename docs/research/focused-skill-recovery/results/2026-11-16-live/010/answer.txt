## Findings

No scored findings.

The contract permits strictly ascending, unique integer rows and a positive integer page size. For an omitted cursor, `select` retains all rows; for a supplied cursor, it retains only values greater than that cursor. `page` takes the first `size` selected rows and returns the last item as the next cursor. Thus, for a nonempty page, the next request excludes every previously emitted row and begins with the next available one.

**Unresolved:** An empty page returns `cursor: undefined`, the same value used to start pagination. The supplied contract does not specify how callers detect completion or whether they may pass that returned cursor into another request. Reusing it would restart selection; stopping when `items` is empty avoids that outcome. Caller behavior is not supplied, so this is unscored.
