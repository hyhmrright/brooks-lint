## Findings

### 🟡 Warning

**R5 Dependency Disorder — Domain bypasses the injected notification function (Warning)**

**Symptom:** `contract.md` requires domain decisions to depend only on an injected notification function, never the HTTP transport module, and requires notification once. `domain.mjs` imports `send` from `http.mjs` and calls it; its `notify` parameter is unused. `entry.mjs` is the supplied active build and passes `send` as that parameter.

**Source:** *Clean Architecture* — Dependency Inversion Principle.

**Consequence:** The source-level boundary is violated. A caller cannot substitute its notification function: `decide('ok', spy)` calls the imported transport instead of `spy`. The current entry still invokes `send` once and returns `sent:ok`, so the supplied snapshot does not establish a missing notification in that path or any deployed impact. This bounded, demonstrated violation supports Warning severity.

**Remedy:** In `domain.mjs`, remove the HTTP import and have `decide` call `notify(x)` once, returning its result. Keep `entry.mjs` responsible for supplying `send`; the domain-to-HTTP import edge then disappears while the entry retains both imports.

## Summary

The active entry preserves one transport call, but the domain’s direct import prevents notification substitution and breaches the explicit dependency rule. The supplied files do not establish deployment reach or team ownership; no checks were executed.
