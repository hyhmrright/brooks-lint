# 006 · Which strings are valid word lists?

The pinned JavaScript modules export a form-field validator. Their shared comment describes a comma-separated list of words. We interpret a list as one or more nonempty words, with optional whitespace immediately after a comma. A word consists of ASCII letters, digits or underscores. Whitespace includes ECMAScript line terminators. The contract covers primitive JavaScript strings with standard built-ins. [Contract](contract.json) · [Original files and license](upstream) · [Pinned upstream revision](https://github.com/hyhmrright/logic-lens/tree/3b158e228127e21bff7be6530e3923de0793a907/evals/real-world/probes/006-redos-catastrophic-backtracking)

| Input | Contract | Original in Node | Fix in Node |
|---|---|---|---|
| Empty string | Reject | Accept | Reject |
| `a,` | Reject | Accept | Reject |
| `a b` | Reject | Accept | Reject |
| `foo, bar` | Accept | Accept | Accept |
| `A_9,` + tab + `z` | Accept | Accept | Accept |

The original allows zero repetitions of the entire word group. Lean checks that zero repetitions consume the empty string and that every derivation of the list grammar contains a word. An optional comma in the original also allows spaces alone between words. Requiring a first word and a comma before each later word restores the documented syntax. [Counterexample](certificates/buggy.lean)

The fixed proof goes in both directions. It decomposes every full match into a first word and a sequence of comma-separated words, and constructs a match for every list generated by the independent inductive grammar. The corollary covers every finite sequence of UTF-16 code units, including lone surrogates. The trusted boundary includes source admission, transcription of the two expressions, character classification and ECMAScript full-string matching semantics with no flags. The theorem models which strings match. The upstream worst-case engine cost obligation remains open. [Kernel-checked proof](certificates/fixed.lean) · [Independent theorem signatures](audit-fixed.lean.inc)

The local runtime observation used Node v26.13.1. For each original module, the runner checks 12 examples, then places every one of the 65,536 UTF-16 units into each of two short contexts. One context isolates a word character and the other checks what may follow a comma before another word character. These 131,072 character checks per implementation supplement the proof with observations from a real engine. [Node runner](observe.cjs) · [Recorded observations and digests](results.json)

## Reproduce

From the repository root, with Python 3.9+, Node.js and Lean 4.19.0 on PATH, run the same command as the Linux Node 22 CI job.

```sh
python3 -I docs/research/logic-lens-006/replay.py
```

The replay checks source digests, installs the skill in a temporary directory, runs the installed checker on both files, checks theorem signatures and axioms, executes each unchanged module as CommonJS, and byte-compares the regenerated certificates and results. Use `--corpus PATH` to read the same pinned sources from a logic-lens checkout. Use `--record` to update the committed evidence after an intentional change.
